# maintain-verification-skill

Periodic upkeep pass for a project-local verification skill and its feature map, such as one generated by `create-verification-skill`. It fans out one read-only source reader per feature file, reconciles their findings, drives every feature live in one coordinated session, triages what it finds into doc drift, harness gaps, or product gaps, and ships at most one PR of proven corrections. Every run ends with one declared outcome: clean, changed, or blocked.

Edits stay inside the verification skill's own directory; product code is never touched, and real regressions are reported rather than papered over in docs.

Invoke it explicitly with `/maintain-verification-skill`. The frontmatter sets `disable-model-invocation: true`, which Claude Code and pi honor, so those hosts never trigger it on their own. OpenCode ignores the field, and Codex controls implicit invocation through its own `agents/openai.yaml` instead.

## Source

Adapted from [Cursor's pstack `maintain-verification-skill`](https://github.com/cursor/plugins/blob/e31650eea443aaea1e84cc15d88c13f40080b275/pstack/skills/maintain-verification-skill/SKILL.md). Local adaptations:

- Default target lookup retargeted from `.cursor/skills/verify-*/` to `.claude/skills/verify-*/`, with `.agents/skills/verify-*/` noted for Codex and pi.
- The source wave falls back to serial reads in the main session when the host has no subagent facility.
- Shipping a `changed` outcome uses a fresh branch that stages only the verification skill's directory, and a local commit plus diff counts as shipped where no PR workflow exists.
- Evidence artifacts are explicitly kept out of the PR, alongside the existing rule for run notes.
- `license: MIT` added to the frontmatter.

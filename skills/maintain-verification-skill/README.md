# maintain-verification-skill

Periodic upkeep pass for a project-local verification skill and its feature map, such as one generated by `create-verification-skill`. It fans out one read-only source reader per feature file, reconciles their findings, drives every feature live in one coordinated session, triages what it finds into doc drift, harness gaps, or product gaps, and ships at most one PR of proven corrections. Every run ends with one declared outcome: clean, changed, or blocked.

Edits cover the verification skill and the project feature map referenced by it. Existing maps bundled inside older verification skills are also supported. Product code is never touched, and real regressions are reported rather than papered over in docs.

People and agents can both invoke it on every supported host. The description names only explicit requests, so ordinary discussion should not start it.

## Source

Adapted from [Cursor's pstack `maintain-verification-skill`](https://github.com/cursor/plugins/blob/ae5650febf4320793844c12c4adaa937f417f8da/pstack/skills/maintain-verification-skill/SKILL.md). Local adaptations:

- Default target lookup retargeted from `.cursor/skills/verify-*/` to `.claude/skills/verify-*/`, with `.agents/skills/verify-*/` noted for Codex and pi.
- The source wave falls back to serial reads in the main session when the host has no subagent facility.
- Feature-map lookup follows the target skill's pointer into project documentation, with support for maps bundled inside older skills.
- Shipping a `changed` outcome uses a fresh branch that stages only reviewed skill and map changes, and a local commit plus diff counts as shipped where no PR workflow exists or the user did not ask for the pass.
- Evidence artifacts are explicitly kept out of the PR, alongside the existing rule for run notes.
- `disable-model-invocation: true` removed, so people and agents can invoke it on every host. OpenCode ignores the field, so explicit-only behavior could not hold everywhere.
- `license: MIT` added to the frontmatter.

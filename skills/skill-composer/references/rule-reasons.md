# Rule Reasons

Read this file in full before writing, moving, or removing the reason for a rule or principle. `SKILL.md` states when a reason is written and where it goes; this file holds the rest.

## What a Reason Is

A reason says why the rule exists, such as context or what goes wrong otherwise. Who stated it, when, and where are not part of it. This governs `SKILL.md` and its references only: a `SPEC.md` Why may quote the author, and a changelog records history by design.

When the author's reason is unknown, ask rather than write a guess. "It is just my choice" is a complete answer, and the rule then gets no reason.

## Beside the Rule or Behind a Why Link

Length does not decide where a reason goes. A long reason that settles a named case keeps that clause beside the rule and links the rest.

A why link (`([why](…))`) is for someone questioning or changing the rule. A run does not follow it, so it needs no read condition.

Two rules in Skill Composer's own `SKILL.md` show the contrast. The rule that pointers target whole files keeps its reason beside it, because the reason settles which fix the author chooses. The byte cap links its reason, because an agent obeys the number either way.

## Reasons and `SPEC.md`

`SPEC.md` holds core pillars, not rule reasons. A pillar's Why stays in its entry, and a rule applying that pillar may link it. An explanation that would otherwise be written in two places lives once in a reference file that both link.

A request to add reasons to rules is answered beside the rules and in references. It never creates or grows a `SPEC.md`.
